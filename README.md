# open-tv-chat

Skype風「世界約130ヶ国語 リアルタイム音声翻訳」対応の
TV会議/ビデオチャットアプリケーション。**現時点は設計ドキュメント段階**であり、
実装(Windows/macOS/Linux/Android/iPhone向けクライアント本体)はまだ着手していない。

## 目的

- [easy-web.tokyo](https://easy-web.tokyo)上で紹介ページを公開し、各OS向け
  クライアントをダウンロードしてもらう。
- **通話本体は利用者端末間の直接P2P通信を基本形とする**(2026-09-26方針変更、
  下記「アーキテクチャ概要」参照)。利用者どうしがお互いの端末にWEBサーバーを
  立てる必要は無い。
- 呼び出し・ルーティングに必要な最小限のシグナリング(セッションID交換等)のみを
  仲介するサーバーとして、[`open-web-server`](https://github.com/aon-co-jp/open-web-server)
  (Apache/Nginx互換のRust製Webサーバー)+ Rust + [`RPoem`](https://github.com/aon-co-jp/RPoem)
  ([WunderGraph Cosmo](https://github.com/wundergraph/cosmo)互換のGraphQL
  Federation実装。REST API不要、Tomcat互換)を運営側(aon-co-jp)が用意する
  想定(利用者端末へのインストールは不要)。
- 音声通話中に、旧Microsoft Skypeのリアルタイム翻訳機能のように、世界約130ヶ国語
  間の音声翻訳を行う。2ヶ国語間の翻訳から開始し、希望すれば最大10ヶ国語まで
  同時に翻訳できるようにする。

## アーキテクチャ概要(構想・2026-09-26 サーバーリレー/P2Pハイブリッド方式に決定)

利用者どうしが互いの端末にWEBサーバーを立てる必要は無くし、かつ**相手に自分の
端末IPアドレスを見せないことを既定(デフォルト)**とするため、通話本体を
「運営側サーバー経由のリレー」を既定モード、「端末間直接P2P」を利用者が明示的に
選んだ場合のみのオプションモードとするハイブリッド方式に決定した。

```
既定モード(プライバシー優先・全員デフォルト):

[クライアントA] ──── 音声/映像 ────► [運営サーバー] ────► [クライアントB]
Win/Mac/Linux/                    (aon-co-jp運営、          Win/Mac/Linux/
Android/iPhone                     open-web-server            Android/iPhone
                                    + Rust/RPoem、
                                    Cosmo互換のリレー/SFU
                                    + 音声翻訳エンジン)
        ◄───────────── 翻訳済み音声/字幕 ─────────────►

  → 相手にはサーバーのIPしか見えない。翻訳(ASR/MT/TTS)もサーバー側で
    一括処理するため、参加者の端末スペックに依存しにくい(最大10ヶ国語同時
    翻訳との相性が良い)。

オプションモード(低遅延優先・利用者が明示的に選択した場合のみ):

[クライアントA] ◄──────── 直接P2P(音声/映像+翻訳) ────────► [クライアントB]
                (運営サーバーは呼び出し/接続情報交換のみ仲介)

  → 直接P2Pに切り替える前に「相手に自分のIPアドレスが見える」旨を明示的に
    警告し、双方の同意を得た場合のみ有効化する。
```

- 既定はサーバーリレー方式のため、TURN中継相当の仕組みを常時前提とする設計と
  なる(NAT越えの成否に依存しない、動作が安定するという利点もある)。
- オプションのP2Pモードは、高速回線・低遅延を優先したい上級者向け機能として
  位置づけ、翻訳処理もその場合は端末側で完結させるか要検討(実装時に詳細化)。
- 通信の暗号化・可用性設計は、既存のミッションクリティカル向け方針
  ([`open-web-server`](https://github.com/aon-co-jp/open-web-server)の
  4層防御通信)をサーバー側に踏襲する。P2Pモードの区間もエンドツーエンド
  暗号化を必須とする。
- 認証・課金・データ保全の考え方は今後 `PORTING.md` / `CLAUDE.md` で詳細化する。

## セキュリティ/プライバシー方針(端末情報の非漏洩)

**既定モードでは相手に自分の端末IPアドレスを見せない**ことを設計上の必須要件と
する。オプションのP2Pモードを選んだ場合のみ、利用者の同意の上でIPアドレスが
相手に伝わることを許容する。

- **既定は必ずサーバーリレー**: 利用者が明示的にP2Pモードへ切り替えない限り、
  音声/映像は常に運営サーバーを経由させ、相手の真のIPアドレスを開示しない。
- **P2Pモードは事前同意制**: P2Pモードへの切り替えは、相手にIPアドレスが
  見える旨を画面上で明示し、双方が同意した場合のみ有効化する(片方だけの
  意思で切り替わらない)。
- **シグナリングは最小情報のみ**: 呼び出し・接続確立に必要な最小限の情報
  (セッションID・公開鍵等)のみを扱い、端末識別子・OSバージョン・ファイル
  パス等の不要な端末固有情報は送信しない。
- **サーバー側ログの最小化**: リレーサーバー側のログにIPアドレス・端末識別子
  等を平文で残さない(必要な場合はマスキング・保持期間の限定を行う)。通話の
  音声/映像・翻訳結果の内容自体はリレー処理後に保存しない(録画機能を提供する
  場合は利用者の明示的な選択によるオプトイン機能として別途設計)。
- **テレメトリ既定オフ**: 利用状況・クラッシュレポート等の送信はデフォルトで
  無効化し、送信する場合は利用者の明示的なオプトインを必須とする。
- **通信は暗号化必須**: クライアント⇔リレーサーバー間・(オプション時の)
  クライアント間P2P区間はいずれもTLS/暗号化を必須とし、平文通信を許可しない。
- **相手への情報開示の最小化**: 通話相手に開示する情報(表示名等)は利用者が
  選択できるようにし、意図しない端末情報(実名・詳細な位置情報等)が自動的に
  相手へ渡らないようにする。

具体的な実装(SFU/リレーの実装方式・TURN相当の帯域設計・P2Pモードの切替UI・
鍵交換方式等)は、`open-web-server`側の既存の4層防御通信方針と整合させながら
実装着手時に詳細化する。

## 音声翻訳エンジンの選定(調査完了・2026-09-26)

商用配布(easy-web.tokyoでの無償/有償配布)を前提に、ASR(音声認識)は
[Whisper](https://github.com/openai/whisper)(MIT、約99言語)、MT(機械翻訳)は
[MADLAD-400](https://huggingface.co/google/madlad400-3b-mt)(Apache-2.0、400+言語)を
軸とする構成を第一候補とした。Meta製のSeamlessM4T/SeamlessStreaming/MMSは言語数・
性能で優位だがCC-BY-NC 4.0(非商用限定)のため製品には採用しない。TTSは
[Piper](https://github.com/OHF-Voice/piper1-gpl)を候補としつつ、声モデルごとに
ライセンスが異なるため個別確認が必要。詳細な比較表・方針は
[`PORTING.md`](PORTING.md)「1. 音声翻訳エンジン調査結果」を参照。

## 多言語表記ルール

対応言語一覧は「英語名 (現地呼称のローマ字表記) = ネイティブ表記 (現地語での言語名)」
の形式で統一する。例:

- Iran (Persia) = فارسی (Farsi)
- Japan = 日本語 (Nihongo)
- France = Français (French)

正式な対応言語一覧(約130ヶ国語分)はISO 639-1/639-3をベースに実装時に機械的に
生成し、上記の表記ルールに沿って人手で現地語ネイティブ表記を確認しながら整備する
(誤ったネイティブ表記を推測で埋めない)。サンプル30件(要ネイティブ話者検証)は
[`PORTING.md`](PORTING.md)「4. 対応言語リスト」に掲載。
